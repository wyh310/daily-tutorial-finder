# 每日教程选题聚合器（Daily Tutorial Finder）

> 一个每日自动从 19 个平台抓取「服务器 / 建站 / AI 工具」类教程、去重归档、生成简报并推送到微信的选题喂料工具。
> 它是我**「内容引流 → 博客沉淀 → 雨云返佣」变现矩阵**里的第一环：**解决"每天拍什么"的内容源问题**。

---

## 一、项目背景：我为什么要做这个

### 1. 我的整体想法（商业模式）

我参考并仿照 B 站 UP 主 **seabell贝海（贝海运维站 / 博客 aabhyun.com）** 的打法，目标是跑通一条**内容引流 + 推广返佣（CPS）** 的变现链路：

```
B站发免费教程视频（钩子/吸量）
        │  视频简介挂博客图文链接
        ▼
自有博客站（沉淀/建信任/SEO 长尾）
        │  图文里嵌入我的雨云专属推广链接
        ▼
用户通过我的链接注册/消费雨云  ──►  我拿返佣
```

本质不是"接广告赚展示费"，而是**联盟返佣**：别人通过我的专属链接买了云服务器，我拿佣金。内容（免费教程）只是钩子，真实变现点在雨云链接。

### 2. 我的资产盘点

| 资产 | 状态 | 说明 |
|---|---|---|
| B站账号 | ✅ 已有 | 引流出口（发免费教程视频） |
| 雨云推广资质 | ✅ 已有专属链接 + 优惠码 | 变现闭环的"钱袋子"，必须带专属标识才返佣 |
| 承接博客站 | 🔧 在建（Next.js 静态站） | 放图文教程，文末自动挂雨云 CTA 转化模块 |

### 3. 我的核心痛点

> **我有账号、有链接、有站，但没有在 B站"持续输出"的内容。**

贝海能每天/每周稳定发"免费 VPS / 免费域名 / 建站教程"，是因为他有一套选题来源。我缺少的就是这个**可持续、不重复的选题供给**——如果每天靠自己瞎想，三天就断更。

### 4. 这个工具解决什么

它就是我的**"每日选题喂料机"**：每天自动去各平台把最新的相关教程/工具捞一遍，去重后把"值得拍的选题"推到我微信。我每天花 5 分钟挑 1~2 条，自己实操一遍，转成**博客图文 + B站视频**发出去。

```
各平台公开教程  ──抓取──▶  本工具（筛选/去重/比对历史库）  ──▶  微信简报  ──▶  我人工选
                                                                                    │
                                                                                    ▼
                                                          写博客图文（母本）+ 剪 B站视频（发布）
                                                                                    │
                                                                                    ▼
                                                          视频简介挂博客链接 + 雨云链接  ──► 变现
```

## 二、功能特性

- **19 个平台聚合**：覆盖国内技术社区 + 海外技术/工具源，避免单一平台刷屏。
- **只抓"最近更新"**：每个源带真实时间戳，按各源"时效窗口"过滤旧内容（高频源窗口短、教程类窗口长）。
- **多平台均衡、防刷屏**：每个源最多展示 6 条，B站再也不会占满整页。
- **两类选题自动分类**：
  - **A 类（服务器/建站）**——强引流，直接挂雨云链接转化；
  - **B 类（工具/AI）**——泛流量，涨粉为主，积累到一定体量再转雨云。
- **数据库归档 + 去重**：每天抓到的选题写入 MySQL，按 URL 去重（`url_hash` 唯一键 + `INSERT IGNORE`），天长日久攒成可检索的选题库；每条还带**优先级评分 `priority`** 字段。
- **简报不推重复内容（核心）**：生成简报前先跟历史库比对，**剔除已推送过的链接，只推"新发现"的选题**，不会天天给你发同一条。
- **内容优先级排序**：每条选题算一个综合得分，**"最值得优先做成你自己的内容"的排在最前面**，简报顶部还有 **「今日优先推荐 Top 5」** 直接告诉你今天先拍哪 5 条。
- **多渠道通知（任选）**：支持 **微信（Server酱）**、**邮件（SMTP）** 两种推送，可通过 `NOTIFY` 切换 `wechat` / `email` / `both` / `none`，零成本、不用自己搭服务器。默认微信。

## 三、实现原理

### 1. 技术栈

- 语言：**Python 3**（标准库 + `requests` + `beautifulsoup4` + `pymysql`）
- 定时：**GitHub Actions**（免费额度内，无需常开服务器）
- 推送：**Server酱**（微信免费推送）
- 存储：**MySQL**（SQLPub 云数据库）

### 2. 抓取方式（按源自适应）

| 类型 | 说明 | 代表源 |
|---|---|---|
| 官方 API | 结构化 JSON，最稳 | Hacker News、GitHub、Stack Overflow、掘金、OSChina |
| RSS / Atom | 标准订阅源 | Medium、Dev.to、Lobsters、少数派、博客园(Atom) |
| 静态 HTML 解析 | BeautifulSoup 提取链接 | CSDN、简书、思否、Gitee、B站(search API)、微信搜狗 |

> 仅抓取**公开信息**，不登录、不爬隐私。B站 / 个别源有频控，脚本已加重试与容错，单源失败不影响整体。

### 3. 处理流水线（`aggregator.py` 的 `main()`）

```
① 拉取 19 个源  ──▶  ② 关键词分类(A/B) + 时效窗口过滤  ──▶  ③ 本批次 URL 去重
       │                                                            │
       │                                           ④ 计算优先级评分 score()（写入 priority 字段）
       │                                                            │
       │                                                  ⑤ 与数据库比对（剔除历史已见）
       │                                                            │
       └──────────────────────────────────────────────▶  ⑥ 仅"新发现"按 priority 排序入库 + 生成简报 + 推微信
```

1. **拉取**：19 个 `fetch_xxx()` 函数并发逻辑（顺序执行，带超时）。
2. **分类 + 时效过滤**：标题/描述命中 `SERVER_KW`/`TOOL_KW` 才保留；按各源 `SOURCE_MAX_AGE` 天窗口过滤旧内容（无时间戳的源保留，最后按热度兜底）。
3. **本批次去重**：同一 URL 本次只留一条。
4. **优先级评分**：对每条调用 `score()`，算出 `priority`（教程信号 / 免费钩子 / 雨云相关性 / 新鲜度 / 热度 / 来源加权），存入数据库并用于排序。
5. **数据库比对去重**：用 URL 的 SHA256 跟 `tutorial_items` 历史库比对，**已存在的剔除**，只留新发现。
6. **排序 + 入库 + 简报 + 推送**：新内容按 `priority` 倒序写入库；简报顶部给「今日优先推荐 Top 5」、正文按源限量展示并标注分数；推微信。

### 4. 时效窗口（`SOURCE_MAX_AGE`，单位：天）

| 窗口 | 平台 |
|---|---|
| 3 天 | Hacker News |
| 7 天 | GitHub、Product Hunt、Reddit、OSChina、博客园、StackOverflow |
| 14 天 | V2EX、Dev.to、Lobsters、CSDN、思否、微信搜狗、Medium |
| 21 天 | 掘金、简书 |
| 30 天 | B站、少数派、Gitee |

> 设计逻辑：资讯类（HN / OSChina）更新快、过期快，窗口短；教程类（B站 / 少数派）长尾性强，窗口长。

### 5. 数据库去重设计

- 表 `tutorial_items`，去重键 `url_hash = SHA256(url)`（CHAR(64) 唯一索引），避免长链接 / 中文 URL 建唯一索引的长度问题。
- 写入用 `INSERT IGNORE`，**重复的不保存**。
- 生成简报前调用 `get_existing_hashes()` 取回全部历史 hash，本批次命中即剔除——保证**微信简报天天都是新货**。
- 每条同时存 **`priority` INT（优先级评分）**，由 `aggregator.score()` 计算（见本节 7），方便日后直接按 `ORDER BY priority DESC` 检索"最该拍的选题"。表结构（`db_store.init_db()` 会自动建，旧表无 `priority` 字段也会自动 `ALTER ADD` 补上）：

```sql
CREATE TABLE IF NOT EXISTS tutorial_items (
    id          INT AUTO_INCREMENT PRIMARY KEY,
    title       VARCHAR(500) NOT NULL,
    url         TEXT          NOT NULL,
    url_hash    CHAR(64)      NOT NULL,   -- SHA256(url)，去重唯一键
    src         VARCHAR(50),              -- 来源平台
    category    VARCHAR(10),              -- A=服务器/建站, B=工具/AI, AB=两沾
    hot         VARCHAR(30),              -- 热度（播放/star/评论）
    pub_date    DATE,                     -- 发布/更新日期
    description VARCHAR(600),
    priority    INT  NOT NULL DEFAULT 0,  -- 优先级评分，越高越值得优先做成自己的内容
    fetched_at  DATETIME NOT NULL,
    UNIQUE KEY uniq_url (url_hash)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 6. 微信推送

未配置 `SERVERCHAN_KEY` 时仅本地生成 `daily_report.md`；配置后通过 `https://sctapi.ftqq.com/{key}.send` 推送简报全文到微信。

### 7. 优先级评分体系（决定"先拍哪条"）

抓到的选题浩如烟海，**核心问题不是"有没有内容"，而是"先拍哪条"**。为此 `aggregator.score()` 给每条算一个整数分，`score` 越高越适合优先做成"你自己的内容"（B站视频 + 博客图文），并用于简报排序。

评分模型对齐你的"雨云返佣漏斗 + 教程化产出"目标，**重点突出"可二创为教程"的信号**（因为你的产出形态就是教程）：

| 维度 | 规则 | 分值 | 设计原因 |
|---|---|---|---|
| 类别权重 | A/AB（服务器·建站，强引流雨云） | **+60** | 这才是直接转化雨云的漏斗入口 |
| | B（工具·AI，泛流量） | +20 | 涨粉为主，暂不直接转化 |
| **教程信号**（最高权重） | 标题含 教程/保姆/搭建/配置/申请/部署/安装/使用/入门/实战/从零/手把手/怎么/如何/步骤/图文/速通/教学 | **+40** | 能照着做的选题 = 你最省力、最易二创 |
| 钩子强度 | 含 免费/free/白嫖/0元/零成本/不要钱 | +30 | 免费教程最易吸量、最易二创 |
| 转化相关 | 含 建站/wordpress/宝塔/cloudflare/域名/vps/云服务器/雨云/主机/面板/服务器 | +15 | 与雨云强相关，顺手转化 |
| 新鲜度 | 3 天内 | +20 | 越新越有时效红利、越易抢发 |
| | 7 天内 | +10 | |
| | 14 天内 | +4 | |
| | 无日期/超期 | 0 | |
| 热度（弱信号） | ≥1000 | +10 | 仅作"已被市场验证"参考，不喧宾夺主 |
| | ≥100 | +5 | |
| | ≥10 | +2 | |
| 平台友好 | B站（本身就是可参照的视频） | +8 | 直接有现成视频参照 |
| | 少数派 | +3 | |

> 实测示例：一条"免费域名注册教程"（A 类 + 教程词 + 免费 + 建站词，微信搜狗来源）得 **145 分**，稳居 Top 5——正是你引流雨云最想要的内容。

简报里每条都标了 `| 优先 XXX` 分数；并单独列出 **「🔥 今日优先推荐 Top 5」**，`final` 列表整体按 `priority` 倒序，你每天照着 Top 5 拍即可，不用自己判断。

## 五、部署到 GitHub（详细步骤，约 20 分钟）

> 目标：零服务器、零成本，每天自动跑 + 存库 + 推通知（微信/邮件）。

### 5.1 配置分工（Variables vs Secrets）

所有配置都通过 GitHub 注入，**不写进代码**。按"是否敏感"分两类：

- **Variables（`Settings → Secrets and variables → Actions → Variables`）**：非敏感配置，明文可见，可放仓库协作说明里。
- **Secrets（同一页的 `Secrets` 标签）**：敏感凭证，加密、不可见，**密码/Key 必须放这里**。

### 5.2 具体参数表

**① Variables（非敏感）**

| 变量名 | 示例值 | 说明 |
|---|---|---|
| `DB_HOST` | `mysql6.sqlpub.com` | 数据库地址 |
| `DB_PORT` | `3311` | 数据库端口 |
| `DB_USER` | `yy_aggregator` | 数据库用户 |
| `DB_NAME` | `yy_aggregator` | 数据库名 |
| `NOTIFY` | `wechat` | 通知渠道：`wechat` / `email` / `both` / `none` |
| `EMAIL_TO` | `you@example.com` | 邮件接收地址（NOTIFY 含 email 时必填） |
| `EMAIL_FROM` | `you@example.com` | 邮件发送账号（即 SMTP 登录账号） |
| `SMTP_HOST` | `smtp.example.com` | SMTP 服务器地址 |
| `SMTP_PORT` | `465` | SMTP 端口（`465`=SSL，`587`=STARTTLS） |

**② Secrets（敏感，切勿泄露）**

| 变量名 | 示例值 | 说明 |
|---|---|---|
| `DB_PASS` | 你的数据库密码 | 数据库密码 |
| `SERVERCHAN_KEY` | `SCTxxxx` | 微信推送 SendKey（[sct.ftqq.com](https://sct.ftqq.com) 扫码获取） |
| `EMAIL_PASS` | 你的邮箱授权码 | 邮箱 SMTP 密码（**注意：多数邮箱是"授权码"而非登录密码**） |

### 5.3 部署步骤

1. **建 GitHub 仓库**：新建一个仓库（公开/私有均可），把本项目全部文件推上去。
2. **配置 Variables**：进 `Settings → Secrets and variables → Actions → Variables`，逐个添加上表①的 9 项。
3. **配置 Secrets**：同一页切到 `Secrets` 标签，逐个添加上表②的 3 项。
4. **启用定时**：工作流默认每天 **北京时间 07:00** 自动跑（`cron: '0 23 * * *'`，即 UTC 23:00）。
   想立刻验证？进 `Actions` 标签页点 `Run workflow` 手动跑一次。
5. **验证成功**：收到通知（微信/邮件）+ 数据库 `tutorial_items` 新增记录 = 部署成功。

> ⚠️ **首次部署建议**：若想从干净状态统计，部署前先执行 `TRUNCATE tutorial_items;` 清空历史（否则会把之前测试数据算进去，不影响功能，只是统计起始点）。

## 七、收到简报后，怎么变成"我自己的内容"（完整方法论）

这是整个链路落地的关键一步。工具只负责"喂选题"，**内容必须自己实操 + 改写**，不能照搬（既是版权红线，也关乎信任）。下面是一套可直接照做的完整 SOP，把"一条外部选题"变成"你自己的图文 + 视频"。

### 7.1 核心原则：搬运 ≠ 抄袭，关键是"实操验证 + 本地化改写"

| 错误做法 ❌ | 正确做法 ✅ |
|---|---|
| 直接翻译 / 复制别人文章发 | 自己**按教程实操一遍**，记录真实步骤和踩坑 |
| 标题、结构、配图照搬 | 用自己的话重写，加入**你的评测结论** |
| 只发不验证，链接失效 | 每个推荐的工具 / 链接，**先验证可用再发** |
| 一条内容只用一次 | **一鱼两吃**：一篇博客图文 → 一条视频，互相导流 |

> 贝海也是这么干的：他的"免费主机 / Orihost"本质是海外资源的二创，但加了中文实操、国内网络适配、自己的优惠码，就成了"他的内容"。

### 7.2 完整流水线（每天 1 小时能出 1 套内容）

```
① 聚合器简报(每天微信推送)
        ↓ 人工挑 1~2 条最值得拍的（优先看 Top 5 / A 类）
② 实操验证：按原始教程自己走一遍，截图/录屏留存
        ↓
③ 写博客图文(markdown) → 放进博客 content/ 目录(已建好)
        ↓ 图文是"母本"
④ 由图文拆出视频脚本(分镜+台词) → 录屏+配音
        ↓
⑤ 发 B站视频(简介挂博客链接+雨云链接)
        ↓
⑥ 博客图文末尾 CTA 挂雨云链接 → 闭环
```

**关键顺序**：先写博客图文、再剪视频。因为图文是你"深度验证"的沉淀，视频只是图文的口语化精简版，省一半精力。

### 7.3 博客图文模板（直接存成 content/xxx.md）

## 八、如何查看 / 检索已存储的选题（数据库）

连上 `mysql6.sqlpub.com:3311` 的 `yy_aggregator` 库，常用查询（已含 `priority` 排序）：

```sql
-- 最近入库的 50 条（看每天新攒了什么）
SELECT title, src, category, priority, pub_date, fetched_at
FROM tutorial_items ORDER BY fetched_at DESC LIMIT 50;

-- 按优先级排序：最该优先拍的选题（综合 score 降序）
SELECT title, src, category, priority, pub_date
FROM tutorial_items ORDER BY priority DESC LIMIT 50;

-- 只看强引流的服务器/建站类（A / AB），按优先级排
SELECT title, url, src, priority, pub_date
FROM tutorial_items WHERE category IN ('A','AB') ORDER BY priority DESC;

-- 按平台统计已攒了多少（看哪个源贡献大）
SELECT src, COUNT(*) FROM tutorial_items GROUP BY src ORDER BY 2 DESC;

-- 总条数
SELECT COUNT(*) FROM tutorial_items;
```

## 十、边界与注意事项

- **只拉公开信息**，不登录、不爬隐私；B站 / 个别源有频控，已加重试与容错。
- **这是"选题喂料机"，不是"自动发 B站"**：它每天给你值得拍的选题，最终拍哪条、怎么改写在你。配合你的选题库节奏发布。
- **内容需自己实操改写**：源教程是"信息差 + 验证"，你的价值在"实测 + 本地化"。照搬既违规也掉信任。
- **无时间戳源**：CSDN / 简书 / 思否 / Gitee / 微信搜狗暂无可靠时间，不按时间过滤（只去重 + 限源）；如需更"新"可改用它们的"最新/热榜"接口或补时间解析。
- **沙箱 vs 部署**：本机/受限网络访问不了的境外源，部署到 GitHub Actions 后自动恢复。

## 十一、数据安全

- **敏感凭证不写死在代码里**：`DB_PASS` / `SERVERCHAN_KEY` / `EMAIL_PASS` 全走 GitHub **Secrets**（加密）；非敏感配置（DB 地址/端口/用户/库名、通知方式、邮件地址、SMTP 地址端口）走 GitHub **Variables**（明文）。二者都在 `Settings → Secrets and variables → Actions` 配置。
- 压缩包与仓库中**不含任何密码**；`.env.example` 仅提供字段样例。
- `INSERT IGNORE` + `url_hash` 唯一键，既防重复又避免明文长 URL 索引问题。
- 未配置 `DB_PASS` 时脚本自动跳过存储，仅本地生成简报，便于调试；未配置完整 SMTP 信息时自动跳过邮件推送。
